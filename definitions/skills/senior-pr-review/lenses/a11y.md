# Lens: Accessibility

Code-level accessibility lens. Find a11y gaps the developer would not catch by visually testing the component in a browser. This critiques rendered code, not designs.

Applies to UI component changes and Storybook stories.

## What to flag

**Semantic HTML**
- `<div>` or `<span>` used where a semantic element exists (`<button>`, `<a>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<header>`, `<footer>`, `<aside>`)
- `onClick` on a non-interactive element without keyboard handling and `role`/`tabIndex`
- Headings out of order (h1 → h3 skipping h2) or multiple h1s on a page
- Lists rendered as flat divs instead of `<ul>`/`<ol>`/`<li>`
- Forms without `<label>` association (`htmlFor` matching `id`, or wrapping label)

**ARIA correctness (sparse is better)**
- Redundant ARIA on already-semantic elements (`<button role="button">`)
- `aria-label` used where visible text would serve
- Missing `aria-label` on icon-only buttons / links
- Wrong ARIA roles (`role="button"` on an `<a>` that navigates)
- `aria-hidden="true"` on focusable elements
- Missing `aria-current` on the active item in navigation
- Modal/dialog patterns without `aria-modal`, focus trap, and Escape handling
- Live regions without `aria-live` or with the wrong politeness level

**Keyboard accessibility**
- Custom interactive components (dropdowns, accordions, tabs) without keyboard handlers (Enter, Space, Arrow keys, Escape)
- Focus order that doesn't follow visual order (positive `tabIndex` values)
- Missing focus styles (CSS `:focus-visible` removed without replacement)
- Focus traps in modals without restore-on-close
- Skip-to-content links missing on long pages

**Images and media**
- `<img>` without `alt` attribute (use empty `alt=""` for decorative images, not omitted)
- Decorative SVGs not marked `aria-hidden="true"` or `role="presentation"`
- Background images conveying meaning without text alternative
- Video without captions / transcript reference
- Auto-playing media without pause/stop control

**Color and contrast (signals, not exact ratios)**
- Color used as the only signal (red text without an icon; "items in red are urgent")
- Text colors set inline (hex / rgb) instead of using design tokens (which are contrast-checked)

**Forms**
- Error messages associated to inputs only via color/icon, not `aria-describedby` or text-in-label
- Required fields marked only with `*` and no programmatic `required` / `aria-required`
- Placeholder text used as the only label
- Input types not specifying `type="email"` / `type="tel"` / `type="number"` where appropriate (affects mobile keyboards)
- Missing `autocomplete` attributes on common fields (`autocomplete="email"`, `name`, `tel`, etc.)

**Dynamic content**
- Content changes that don't announce to screen readers (toasts, validation errors, async loading) without `aria-live` or `aria-atomic`
- Loading states that show a spinner without `aria-busy` or text alternative
- Infinite scroll without an accessible "Load more" alternative

**Internationalization (overlaps with Conventions but lives here for a11y impact)**
- Hardcoded user-facing strings instead of the i18n system — screen readers in non-English locales will read English

## What NOT to flag

- Storybook story files unless the story renders user-facing UI patterns being audited
- Test files
- Internal admin tools where a11y scope is documented as limited (back-office, dev-only screens) — but still flag obvious wins
- Color contrast ratios you can't verify (don't fabricate; flag only "color as sole signal" patterns)
- Anything where the project's design tokens already handle the concern correctly

## Output

Return candidates only: for each one give file, line range, the quoted hunk, the concrete failing scenario (or attack scenario, or the user blocked) and the smallest repair. No severity tags; the parent review assigns severity after it verifies each candidate against the current head. If you find nothing of substance, return `No findings`.
