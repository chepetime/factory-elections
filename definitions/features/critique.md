# Critique the spec

Critique the spec below as the agent that must build it and the agent that must verify it. You may read the repository.

Report, as a Markdown list ordered by severity:

- Gaps: anything a builder would have to guess.
- Contradictions with the code or within the spec, with file paths.
- Acceptance checks that cannot be verified as written, and how to make them verifiable.
- Scope that is too large for small tickets, and where to cut it.

Be specific. Do not rewrite the spec. Reply with only the list.
